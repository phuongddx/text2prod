Chapter 2

Route work through zed-mode

zed-mode is the front door. You give it a goal. It matches the goal to one of 23 playbooks, copies the playbook's steps into a todo list, and calls the skill each step names. Name the playbook in your prompt when its steps matter.

The skill-first rule

Before the agent replies or acts, it checks whether a skill applies. That includes clarifying questions: the check comes first, then the questions. When it finds a match, it announces "Using [skill] to [purpose]" and follows the skill.

When several skills apply, process skills go first because they set the approach. "Let's build X" starts with brainstorming. "Fix this bug" starts with systematic-debugging. Implementation skills carry out the approach afterwards.

What happens to your prompt

The router reads the goal and picks the kind of work. Each route below ends by verifying the result and reporting with evidence.

The diagram shows the main routes, not every playbook. The release evals found that on a plain bug report no session produced the bug-fix step list on its own, with or without the plugin. Name the playbook ("use the bug-fix playbook") and you get its steps.

A step the agent decides not to run stays in the list as skip: <reason>, so you can see what was left out. The opening-a-pr playbook closes change playbooks such as bug-fix, feature, and refactoring. The read-only investigation playbook opens no PR.

What goes in a prompt

A good prompt has up to five parts. Each one fits on a line.

  • The goal: what should be different when the work is done.
  • A done check that can pass or fail, so the agent cannot call it done on its own say-so.
  • The proof you want to see, such as output, a screenshot, or before and after numbers.
  • What you already know: ids, dates, the failing job, what you ruled out.
  • Real constraints, such as "reproduce it first" or "don't change code yet".

Here is one prompt with all five parts:

/text2prod:zed-mode use the bug-fix playbook. the csv export drops its last row since tuesday's deploy. failing job is 4812. reproduce it first, then fix it. done means the 60k-row fixture exports every row. show me the row counts before and after.

Leave out the how. The playbook already says how. Also hold back your theory of the cause until the agent has restated the problem in its own words. An early theory can anchor the investigation on the wrong place.

When nothing fits

When no playbook fits, or the work is large, cross-cutting, or reviewed after you step away, the agent runs figure-it-out. It starts by naming the playbooks it considered and why none fits.

Then it frames a done condition that can be checked, designs the phases, runs each one as a measured experiment, and keeps a decision trail you can read later. Reach for it on a migration across many call sites, or on any task you plan to audit after the run.
